# Axion Screens — библиотека экранов Gen, Command & Control и Sense

Движок, который сам снимает интерфейсы продуктов Axion, раскладывает их по флоу в духе Mobbin, обезличивает чувствительные данные, хранит версии и регулярно обновляет базу. Каждый экран есть в PNG (Retina) и в редактируемом SVG: текст остаётся текстом, плашки — фигурами, поэтому их можно сразу открыть в Figma. Агенты (Claude Code, Claude Desktop, Cursor) работают с библиотекой через MCP: находят нужный экран и забирают готовый к слайду файл.

Зачем: визуалы для презентации ПЧДК и сайта, бренд-гайд (экраны на прозрачном фоне и отдельные плашки), единый архив скриншотов, который сам обновляется вслед за стендами.

```
scrn refresh
  ├─ обход приложения (discover) ─ все разделы и вложенные пункты меню, вкладки, фильтры, карточки
  │    └─ флоу по разделам: _planning, _inspectors… (сверх каталога)
  ├─ флоу из catalog/products/*.yaml ─ шаги → экраны → плашки
  │    └─ для каждого экрана: обезличивание (API → DOM) → guard → съёмка Retina
  │         → варианты: с фоном / .clear / .cards / .full / плашки — в PNG и редактируемом SVG
  ├─ диф с прошлой версией → новая версия, только если экран реально изменился
  ├─ автотеги и privacy-аудит (Claude Code по твоей подписке, без API-ключа)
  ├─ галерея library/index.html (экспорт PNG 1x/2x/3x, SVG, подложки — через scrn serve)
  └─ git commit + push (PNG и SVG в Git LFS)
```

## Быстрый старт

```bash
git lfs install
npm install                      # заодно собирает dist/
./scrn go                        # всё за один раз
```

`scrn go` ставит Chromium, проверяет сессии и открывает окно браузера только там, где нужно войти через SSO/2FA. Дальше он сам снимает все флоу из каталога и всё, что нашёл обход приложения, размечает новые экраны через Claude Code и открывает галерею на http://127.0.0.1:4567 (в ней работает экспорт; Ctrl+C — остановить). Повторный запуск обновляет базу: новые версии появляются только у изменившихся экранов.

По шагам то же самое выглядит так:

```bash
./scrn auth gen && ./scrn auth cnc   # вход в стенды (C&C и Sense делят одну сессию)
./scrn doctor                        # проверка каталога, браузера, сессий
./scrn capture brief --tag           # 5 экранов из брифа + автотеги
./scrn serve --open                  # галерея с экспортом
```

Для мобильных макетов из Figma нужен `FIGMA_TOKEN` в `.env` (шаблон — `.env.example`).

`./scrn` — обёртка над `node dist/cli/index.js`: после `git pull` она сама доставит новые зависимости и пересоберёт `dist/`. Если хочется глобальную команду `scrn`, выполни `npm link` (тогда после обновления — `npm install`).

## Как устроена библиотека (механика Mobbin)

| Mobbin | Здесь |
|---|---|
| App + платформа | продукт (`gen`, `cnc`, `sense`) × `desktop` / `mobile` |
| Flow — последовательность экранов | флоу в `catalog/products/<product>.yaml`: шаги выполняются по порядку в одной вкладке |
| Screen с паттернами и элементами | шаг = экран; `patterns` и `elements` из `catalog/taxonomy.yaml` плюс автотеги Claude |
| Sections | `sections` шага: изолированные плашки (KPI, графики, таблицы) без фона |
| Весь каталог приложения | обход разделов: каждый раздел меню становится флоу `_<раздел>` — страницы, вкладки, фильтры, карточки |
| Версии приложения | новая версия экрана появляется, только если изменилось больше 0.4% пикселей (или поменялись правила обезличивания); история хранится в git |

Отдельный слой — **бриф**: у флоу стоит `brief: <id>` для одного из пяти экранов презентации. И в галерее, и в MCP их можно отфильтровать.

| Бриф | Где снимаем | Статус |
|---|---|---|
| `quality-check` — проверка качества | Sense → `/frames?imageQuality=rejected` + разбор кадра | готово к съёмке |
| `executive-summary` — сводка для руководителя | Gen → `/dashboards`, C&C → `/{org}/dashboard` | готово к съёмке |
| `decision-card` — карточка решения (HITL) | C&C | `todo`: актуального интерфейса может не быть |
| `agent-work` — агентная работа, диалоги | Gen | `todo`: нужен URL ассистента |
| `customer-system-task` — задача во внешней системе | C&C | `todo`: интерфейса может не быть |

Флоу с `todo:` пропускаются, пока их не уточнят (`./scrn doctor` выводит их список). Подробнее о формате — в [docs/catalog.md](docs/catalog.md).

### Что лежит в `library/`

```
library/
  index.json                                   ← каталог: экраны, флоу, версии, теги, прогоны
  index.html                                   ← галерея
  gen/desktop/executive-summary/
    01-dashboards.png                          ← экран с фоном, 2880×1800 (@2x)
    01-dashboards.clear.png                    ← фон приложения прозрачный, карточки на месте
    01-dashboards.cards.png                    ← только плашки: без фона, сайдбара и шапки
    01-dashboards.full.png                     ← вся страница, если контент не влез в первый экран
    01-dashboards.svg                          ← то же в векторе: текст — текстом, плашки — фигурами (для Figma)
    01-dashboards.clear.svg / .cards.svg / .full.svg
    01-dashboards.thumb.webp                   ← превью (лежит в обычном git)
    02-dashboard--kpi-row.png / .svg           ← изолированная плашка со своими скруглениями и тенью
  cnc/desktop/_planning/…                      ← флоу из обхода: раздел «Planning» со всеми подпунктами,
    planning-schedule.png                         вкладками, панелями фильтров и карточками
    planning-schedule-tab-list.png
    planning-schedule-panel-filters.png
```

Мобильные экраны снимаются в разрешении iPhone 15 Pro: 1179×2556 (@3x), десктоп — 2880×1800 (@2x). Такие картинки без пересчёта вставляются в макапы устройств. Разрешения задаются в `scrn.config.yaml → platforms`. Полноразмерные PNG и SVG хранятся в Git LFS, превью и `index.json` — в обычном git, поэтому галерея работает и без `git lfs pull`.

SVG собирается из живой (уже обезличенной) страницы в момент съёмки: текст, карточки, рамки, градиенты, иконки и тени (в формате drop shadow, который Figma распознаёт как эффект) — векторами. То, что браузер рисует пикселями, — графики на canvas, карты, видео, нативные чекбоксы, размытые фото — вставляется картинкой с того же кадра. Шрифты страницы встраиваются, чтобы SVG выглядел так же и вне Figma.

## Команды

| Команда | Что делает |
|---|---|
| `scrn go` | Всё за один раз: браузер → вход, где нужно → съёмка всех флоу и разделов → автотеги → галерея |
| `scrn doctor` | Проверяет каталог (схемы, CSS-селекторы, TODO), браузер, сессии, ключи, LFS |
| `scrn auth <product>` | Открывает браузер для входа через SSO/2FA и сохраняет сессию в `.auth/` (в git не попадает). `--check` проверяет сессии без окна |
| `scrn capture [targets]` | Снимает экраны: `brief`, `gen`, `gen/executive-summary`, `cnc/inspectors/profile`. Флаги: `-p mobile`, `--headed`, `--dry-run`, `--force`, `--tag` |
| `scrn discover [product]` | Обходит приложение: раскрывает свёрнутые группы меню, жмёт пункты без ссылок, открывает вкладки, фильтры и карточки. Снимает всё как флоу по разделам и пишет подсказку в `catalog/discovered/<product>.yaml`. Флаги: `--depth`, `--max`, `--no-capture` |
| `scrn refresh` | Полное обновление: discover → все флоу → диф → автотеги → галерея. Флаги: `--commit --push`, `--prune`, `--no-tag` |
| `scrn tag` | Автотеги и privacy-аудит новых и изменившихся экранов: headless Claude Code по подписке, без API-ключа |
| `scrn export <запрос или id>` | Файлы для слайдов: `--variant framed --bg blur`, `clear`, `cards`, `full`; `--format svg` (вектор, `--svg raster` — пиксель в пиксель), `--scale 1/2/3` для PNG |
| `scrn list`, `scrn history <id>` | Список экранов и их версии в git |
| `scrn serve --open` | Галерея на http://127.0.0.1:4567 с экспортом: PNG 1x/2x/3x, SVG (вектор или растр), подложки |
| `scrn gallery --open` | Галерея с диска: только готовые файлы (PNG в снятом масштабе и SVG) |
| `scrn mcp` | MCP-сервер (stdio) |
| `scrn watch`, `scrn schedule install` | Периодическое обновление |

Примеры экспорта:

```bash
./scrn export "сводка KPI" --variant framed --bg blur          # экран на размытом фоне из самого себя
./scrn export "сводка KPI" --variant clear --scale 1           # PNG @1x (1440 px), без фона приложения
./scrn export gen.desktop.executive-summary.dashboard --format svg                # редактируемый SVG для Figma
./scrn export gen.desktop.executive-summary.dashboard --variant framed --format svg   # на подложке, тоже вектор
./scrn export gen.desktop.executive-summary.dashboard --variant cards --padding 32
./scrn export gen.desktop.executive-summary.dashboard --variant layers   # растровые слои: фон можно выключить в Figma
```

Масштаб PNG считается от CSS-размера, как в Figma: `--scale 1` — 1440 px по ширине десктопа, `2` — Retina 2880 px (как снято), у мобильного есть ещё `3`. Больше снятого не бывает: на `--scale 3` для десктопа придёт @2x с пометкой. Имена файлов понятны сами по себе: `Axion Gen · Сводка для руководителя · 02 Дашборд с KPI (desktop, en, framed)@2x.png`.

В галерее то же самое делается кнопками: в карточке экрана есть панель «Экспорт» — вариант (с фоном, без фона, только плашки, вся страница, на подложке), формат PNG или SVG, масштаб 1x/2x/3x, вектор или растр, подложка, отдельные плашки. Всё это считает `scrn serve`; галерея, открытая с диска, отдаёт только готовые файлы.

## Обезличивание: только чувствительные данные

Экраны могут стать публичными, поэтому реальных данных на них быть не должно. Меняется только чувствительное: люди, контакты, номера машин и документов, заказчики и их логотипы. Названия разделов, пунктов меню, вкладок, заголовки, подписи и цифры интерфейса остаются как есть.

1. **API.** JSON-ответы (`anonymize.network`) проходят через словарь ещё до отрисовки. Так обезличиваются и графики на canvas, и карты, и тултипы. Идентификаторы и enum-константы не трогаются, чтобы не сломать логику приложения.
2. **DOM.** Текст, атрибуты, инпуты, SVG-подписи графиков, shadow DOM. Селекторные правила (`person`, `org`, `email`, `digits`, `chars`, `text`) работают для полей, где имена заранее неизвестны (инспекторы, пользователь в сайдбаре). Правило срабатывает, только если значение похоже на то, что оно меняет: номер (`chars`) — с цифрами и без строчных слов, e-mail — с `@`, имя — несколько слов без цифр. Внутри навигации, меню, вкладок и деревьев правила не работают вовсе (кроме имени и почты текущего пользователя), а совпадение, под которым много текста, считается случайным контейнером и пропускается. Логотипы заказчиков заменяются логотипом Axion (`assets/anonymize/logo.svg`; на тёмном фоне — белым), аватары — инициалами персоны, фото можно размыть.
3. **Guard.** Перед публикацией всё, что видно на экране, проверяется по блок-листу (реальные люди, Momra/Balady и т. д.) и по шаблонам PII. Если что-то нашлось, экран в библиотеку не попадает и уходит в `.scrn/quarantine/`.
4. **Privacy-аудит Claude** (при разметке) смотрит на пиксели: лица, номера машин, логотипы, имена не из списка персон. Значения, которые подставило обезличивание, передаются ему как безопасные, поэтому фейковый телефон не считается утечкой. Подозрительный экран получает статус `review`, и MCP не отдаёт его по умолчанию.

Замены детерминированы: реальный человек на всех экранах и при каждом обновлении превращается в одну и ту же персону, арабские имена — в арабские. Словарь лежит в `catalog/anonymize.yaml`, правила под конкретный продукт — в `catalog/products/*.yaml → anonymize`. Если поменять правила, словарь или логотип, следующий `refresh` перепишет затронутые экраны, даже если разница в пикселях меньше порога.

Селекторы правил пиши по началу класса, а не по подстроке: `[class*='plate' i]` ловит и `template` (Tailwind-класс `transition-[grid-template-rows]` у раскрывающихся групп меню — так в сайдбаре и появлялись «Agvqtxujmhp & rkndfybj»). Надёжный вариант — `[class^='plate' i], [class*=' plate' i], [class*='-plate' i], [class*='Plate']` или `data-testid`.

> Репозиторий должен оставаться приватным: в словаре перечислены заказчики, которых нельзя светить. Сессии (`.auth/`), карантин и дампы ошибок (`.scrn/`) в git не попадают.

## Автотеги без API-ключа

Размечает сам Claude Code по твоей подписке. Через MCP он видит превью экрана и его контекст (продукт, флоу, маршрут, обезличенный текст) и сохраняет:
- паттерны и UI-элементы из `catalog/taxonomy.yaml`;
- описание и ключевые слова на русском и английском;
- где экран уместен в презентации (`suggestedUse`);
- проблемы качества (обрезано, пустое состояние, лоадеры);
- privacy-аудит.

Два способа:

- **Вручную в Claude Code:** открой Claude Code в этой папке и выполни `/tag-screens`. Claude берёт очередь через `tagging_queue` и пишет теги через `save_tags`.
- **Автоматически:** `scrn tag` и `scrn refresh` запускают Claude Code без интерфейса (`claude -p`). У этого запуска нет Bash и доступа к файлам, только два инструмента разметки, а значит он может только смотреть превью и записывать теги. Нужен установленный и залогиненный `claude` CLI.

```bash
./scrn tag --dry-run         # что будет размечено
./scrn tag --limit 10        # разметить 10 экранов
```

Заново размечаются только экраны с изменившимися пикселями. Если API-ключ всё-таки появится, есть `tagging.provider: api`.

## Периодическое обновление

Стенды требуют SSO, поэтому обновление крутится на машине дизайнера, а не в CI:

```bash
npm run build
./scrn schedule install            # macOS: launchd, Linux: crontab — по cron из scrn.config.yaml (пн 07:00)
./scrn schedule install --cron "0 7 * * 1-5"
```

Расписание запускает `scrn refresh --commit --push`. Если сессия истекла, придёт системное уведомление, в логе `.scrn/schedule.log` будет подсказка, а старые версии экранов останутся на месте. Чтобы не ставить в планировщик, есть `./scrn watch --now` — процесс, который сам запускает обновление по расписанию.

## MCP: экраны для агентов

В репозитории лежит `.mcp.json`, поэтому Claude Code, открытый в этой папке, сразу видит сервер `axion-screens`. Для Claude Desktop добавь в `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "axion-screens": { "command": "node", "args": ["/ПУТЬ/К/axion-scrn-gallery/dist/cli/index.js", "mcp"] }
  }
}
```

| Инструмент | Зачем |
|---|---|
| `search_screens` | Поиск экранов по смыслу на русском и английском, фильтры `product`, `platform`, `pattern`, `element`, `brief` |
| `search_flows` | Сценарии: последовательности экранов, как в Mobbin |
| `search_sections` | Отдельные плашки: KPI, графики, таблицы на прозрачном фоне |
| `get_screen`, `get_flow` | Карточка экрана или флоу с превью |
| `export_screen` | Готовые файлы: `clear`, `cards`, `framed`, `layers`; `format: png` со `scale` 1/2/3 или `format: svg` (`svg_mode: vector` или `raster`) |
| `list_products`, `library_status` | Что есть в библиотеке, покрытие брифа, ошибки, карантин, сессии |
| `capture` | Переснять экран со стенда |
| `tagging_queue`, `save_tags` | Разметка экранов самим агентом (так работает `/tag-screens`) |

Ресурсы: `screen://<id>` (PNG) и `library://index`. В Claude Code есть команды `/tag-screens` (разметить новые экраны) и `/screens-for-slide <тезис>` (подобрать экраны и сделать файлы для слайда).

Пример запроса агенту: «Найди в axion-screens экран сводки KPI из Gen и сделай framed на размытом фоне для слайда про руководителей».

## Ограничения

- Текст, который приложение рисует на canvas или WebGL из захардкоженных строк (а не из API), DOM-слой не видит. Такие места закрывает только сетевой слой или privacy-аудит Claude. В SVG такие области — картинки, а не текст.
- Обход нажимает только безопасное: раскрывает группы меню, пункты навигации, вкладки, кнопки фильтров и колонок, первую строку таблицы. Всё, что похоже на удаление, отправку, сохранение, подтверждение, экспорт или выход (на английском, русском и арабском), не нажимается никогда. Кнопки «Создать» обход не трогает: такие экраны описывай в каталоге.
- Если раздел приложения не нашёлся, обход его не видит в навигации — добавь шаг в каталог или его ссылку в `discover.navSelectors`.
- Фото с камер (лица, номера) по умолчанию не размываются: это суть продукта Sense. Для публичных материалов включи `anonymize.blur` в `catalog/products/sense.yaml`.
- Селекторы в каталоге подобраны общие (`[class*='user-name' i]` и т. п.). После первого `./scrn capture --headed` их стоит уточнить по реальной вёрстке, а лучше договориться с фронтендом о `data-testid`.
